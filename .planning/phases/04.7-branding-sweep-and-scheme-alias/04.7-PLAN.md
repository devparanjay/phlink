# Phase 4.7 — Branding Sweep + scheme alias — PLAN

> Decisions in `04.7-CONTEXT.md`. Pattern follows Phase 3 / Phase 4.6 (root-subtree patches in chromium-src, mirrored into `patches/` slot 0013–0029 in the phlink repo). ## Phase boundary

- **In scope:** GRD branding sweep (audit + targeted patches), `tests/branding-audit/` harness, manual smoke checklist documented in `tests/branding-audit/SMOKE.md`.
- **Out of scope:** `phlink://` scheme registration (deferred — placeholder slot 999.4); logo/icon refresh (placeholder 999.5); locale translations (Phase 11).

## Plans

### 04.7-01 — Build the binary-string audit harness

Create `tests/branding-audit/` with:

- `audit.sh` — runs `strings` against `phlink.app/Contents/MacOS/phlink` AND `phlink.app/Contents/Frameworks/phlink Framework.framework/Versions/<v>/phlink Framework`, greps for `(?i)\bchromium\b|google chrome`, diffs against `allowlist.txt`, exits non-zero on unexpected matches. Resolves the framework version dynamically.
- `allowlist.txt` — explicit allowlist of acceptable matches (third_party debug paths, devtools URLs, GRD `<ex>` translation hints, GL_RENDERER, hardcoded brand-check guards that don't fire on phlink). Each entry annotated with rationale comment.
- `SMOKE.md` — manual smoke-test checklist (about box, app menu, settings landing, `chrome://version`, `chrome://flags`, omnibox URL display) with screenshot-anchor placeholders.
- `README.md` — how to run + interpret.

Acceptance: `./audit.sh` exits 0 against the current build, and prints a one-line summary `branding-audit: N strings matched, all on allowlist`.

### 04.7-02 — Seed the allowlist from current build

Run the audit once, classify every match, and either:

- Add to allowlist with category tag (`# category: third-party-debug-path`, `# category: devtools-url`, `# category: grd-translation-ex`, `# category: gl-renderer`, `# category: brand-check-guard`, `# category: native-messaging-path`).
- Mark for patching in subsequent plans.

Output: `allowlist.txt` populated; second `./audit.sh` run is green.

### 04.7-03 — Patch any genuinely user-visible "Chromium" strings discovered in 04.7-02

Conditional plan: only fires if 04.7-02 surfaces strings that (a) are user-visible AND (b) are not driven by IDS_PRODUCT_NAME substitution. Candidates flagged from initial audit:

- `Chromium PDF Viewer` — likely GRD `<ex>` artifact, NOT runtime string. Confirm in 04.7-02.
- `Chromium NetLog` — used as `chrome://net-export` download filename. If hardcoded, replace with `IDS_PRODUCT_NAME` substitution.
- `Chromium Apps.localized`, `Chromium Initial Preferences`, `Chromium Master Preferences` — installer / data-dir constants. Generally driven by BRANDING file (Phase 3 already remapped). Confirm.

Each patch goes into a slot in `0013–0029`, mirrored from chromium-src to `phlink/patches/`. If 04.7-02 finds nothing user-visible to patch, mark this plan as N/A.

### 04.7-04 — Smoke-test the built binary against `SMOKE.md`

Launch the existing build, walk through `SMOKE.md` checklist, record findings in `tests/branding-audit/SMOKE-RESULTS-<date>.md`. Any FAIL items go back into 04.7-03 as additional patches.

### 04.7-05 — Wire harness into build documentation

Add a single line to `docs/dev/build.md` (or create the file if absent) noting `tests/branding-audit/audit.sh` as the standing branding regression gate.

### 04.7-06 — Mark roadmap; commit + push

Update `.planning/ROADMAP.md`: mark Phase 4.7 complete with a one-line status referencing the audit harness location and the `SMOKE-RESULTS-*.md` file. Commit and push to `dev-0.1`.
