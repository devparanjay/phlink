## Gray areas (decision matrix)

### G-01 — Internal canonical scheme

**Question**: Should `phlink://` replace `chrome://` internally, or alias on top?

| Option | Pro | Con |
|---|---|---|
| (a) Replace — `kChromeUIScheme = "phlink"` | Cleanest, single source of truth | Touches ~4,700 files, breaks rebase, history migration nightmare |
| (b) Alias — `phlink` is added scheme, rewrites to `chrome` | Minimal blast radius, matches Brave's known-working approach | Two schemes coexist forever |

**Chosen: (b).** Codified as **D-01**. Alignment with PRD §10.1 ("minimal patch set").

### G-02 — Where to install the rewrite

**Question**: At which layer do we translate `phlink://` to `chrome://`?

| Option | Pro | Con |
|---|---|---|
| (a) `URLLoaderRequestInterceptor` | Modern, async-clean | More machinery; runs after navigation start |
| (b) `BrowserURLHandler::AddHandlerPair` | Documented, used by `about:` → `chrome://`, runs before navigation commit | Older API surface |
| (c) `WebUIControllerFactory::CreateWebUIControllerForURL` | Local to WebUI dispatch | Misses non-WebUI consumers (omnibox, history, autocomplete) |

**Chosen: (b).** Codified as **D-04**. Same precedent the upstream uses.

### G-03 — Reverse rewrite scope

**Question**: When showing a `chrome://X` URL in the omnibox, do we always show `phlink://X`, or only for some hosts?

| Option | Pro | Con |
|---|---|---|
| (a) Always rewrite | Most consistent | Surfaces internal `chrome://internals/...` URLs as `phlink://internals/...` which are still dev-only |
| (b) Allow-list canonical hosts | Conservative, avoids over-rebranding | Maintenance burden as new WebUI pages appear |

**Chosen: (b).** Codified as **D-05**. Allow-list seeded with the 12 user-facing hosts.

### G-04 — Phase scope ceiling

**Question**: Do we ship full SC-4 (all internal cross-references emit `phlink://`) and SC-5 (gtest coverage of rewrite mapping) in 8.6, or split?

| Option | Pro | Con |
|---|---|---|
| (a) Full ROADMAP SC 1–5 in 8.6 | Closes the criterion | Large patch surface, build-break risk |
| (b) SC 1–3 hard, SC 4–5 soft / best-effort | Bounded patch | Leaves SC-4/5 as soft gates |

**Chosen: (b).** Codified as **D-02**. Same lesson as Phase 8.5.

### G-05 — `phlink://` security tier

**Question**: secure scheme? Standard scheme? Savable?

| Option | Pro | Con |
|---|---|---|
| (a) Match `chrome://` exactly: standard + secure | Identical security posture | Implies same renderer constraints |
| (b) Standard only, not secure | Lower privilege | Mixed-content warnings inside our own WebUI |

**Chosen: (a).** Codified as **D-06**.

### G-06 — History dedup

**Question**: De-dup `chrome://settings` and `phlink://settings` in history DB?

| Option | Pro | Con |
|---|---|---|
| (a) Dedup | Cleaner history | Schema/migration complexity |
| (b) No dedup, both appear | Trivial | Slight UX confusion |

**Chosen: (b).** Codified as **D-07**.

### G-07 — Autocomplete bias

**Question**: When the user types `chr` should the omnibox push them toward `phlink://` instead?

| Option | Pro | Con |
|---|---|---|
| (a) Bias toward `phlink://` | Reinforces brand | Surprising, breaks muscle memory |
| (b) Honor what user types | Predictable | Slower brand adoption |

**Chosen: (b).** Codified as **D-08**.

### G-08 — Verification mechanism

**Question**: How do we verify the alias works?

| Option | Pro | Con |
|---|---|---|
| (a) Add gtest in `chrome/browser/ui/...` | High signal, slow to write | Tests bound to internals |
| (b) Extend runtime CDP audit (Phase 8.5's harness) | Reuses existing Python infra, exercises the real browser | Less unit-level coverage |
| (c) Both | Best | Cost |

**Chosen: (b) for 8.6, (c) deferred to 8.6.x if needed.** Codified as **D-09**.

### G-09 — Patch slot count

**Question**: Split into 4 patch slots (one per touchpoint) or one?

| Option | Pro | Con |
|---|---|---|
| (a) 4 slots | Atomic per-layer | Each slot would build-break the previous one (e.g., scheme registration without rewrite handler = broken navigation) |
| (b) 1 atomic slot | Builds clean at every commit | Larger single diff |

**Chosen: (b) — slot 0117.** Codified as **D-03**.

**Question**: What's explicitly punted?

Codified as **D-10**. Notable defers: bookmarks migration, translations, `phlink-extension://` etc., scheme constant rename. None of these block 8.6's success criteria.
