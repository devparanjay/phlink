# Release Process

> End-to-end release flow from a clean `dev-0.1` branch to signed artifacts on the GitHub releases page.
> Companion to [release-keys.md](release-keys.md) (key inventory and ceremony) and [installers.md](installers.md) (installer build scripts).

## 1. Overview

A phlink release has four stages:

1. **Key generation ceremony** (one-time, air-gapped) — generates the TUF signing keys.
2. **Build** — compiles the browser binary and helpers for all three platforms.
3. **Package** — wraps the build output into platform installers (`.dmg`, `.AppImage`, `.deb`, `.rpm`, `.msi`).
4. **Sign and publish** — signs each artifact, produces a TUF envelope, and uploads to GitHub Releases.

Stages 2–4 are scripted.
Stage 1 is documented in [release-keys.md](release-keys.md) and run once per key rotation.

---

## 2. Key generation (one-time)

Run on an air-gapped machine.
See [release-keys.md § Initial key generation ceremony](release-keys.md) for the full procedure.

Script: [`scripts/release/keygen.sh`](../../scripts/release/keygen.sh)

What it generates:

| Key | Type | Purpose |
|-----|------|---------|
| TUF root key | Ed25519 | Signs `root.json`; stored offline (USB + safe). |
| TUF targets key | Ed25519 | Signs `targets.json`; used per-release (HSM or encrypted USB). |
| GPG release key | Ed25519 | Detached `.asc` signature on Linux artifacts. |
| EV Authenticode cert | RSA-2048 | Signs the Windows `.msi` (CI-only; not generated by this script). |
| Developer ID cert | RSA-2048 | Signs the macOS `.dmg` (CI-only; not generated by this script). |

## 3. Build

From a Chromium checkout with the phlink patch series applied:

```sh
export PATH="$HOME/depot_tools:$PATH"

# macOS / Linux
caffeinate -is autoninja -C out/Default chrome

# Windows (PowerShell)
autoninja -C out\Default chrome
```

Verify the build is healthy:

```sh
# macOS — must codesign before running tests
codesign --force --deep --sign - out/Default/phlink.app

autoninja -C out/Default unit_tests
out/Default/unit_tests --gtest_filter="Phlink*"
```

## 4. Package (create installers)

Run the relevant script from the phlink repo root (not the Chromium checkout).
Each script expects `BUILD_DIR` to point to the Chromium `out/Default` directory.

### macOS

```sh
BUILD_DIR=/path/to/out/Default bash installers/mac/build-dmg.sh
# Output: phlink-<version>-mac.dmg
```

Optionally pass a Developer ID identity:

```sh
BUILD_DIR=/path/to/out/Default SIGN_IDENTITY="Developer ID Application: ..." \
  bash installers/mac/build-dmg.sh
```

### Linux (AppImage)

```sh
BUILD_DIR=/path/to/out/Default bash installers/linux/build-appimage.sh
# Output: phlink-<version>-x86_64.AppImage
```

### Linux (`.deb` / `.rpm`)

```sh
BUILD_DIR=/path/to/out/Default bash installers/linux/build-packages.sh
# Output: phlink_<version>_amd64.deb, phlink-<version>-1.x86_64.rpm
```

### Windows (`.msi`)

```powershell
$env:BUILD_DIR = "C:\path\to\out\Default"
.\installers\windows\build-msi.ps1
# Output: phlink-<version>.msi
```

See [installers.md](installers.md) for full prerequisites and signing notes.

## 5. Sign and publish

Script: [`scripts/release/sign-release.sh`](../../scripts/release/sign-release.sh)

```sh
bash scripts/release/sign-release.sh \
  --artifacts-dir dist/ \
  --targets-key path/to/targets.key \
  --gpg-key-id <GPG_KEY_ID>
```

What the script produces:

- Per-artifact GPG detached signature (`.asc`) for Linux packages and AppImage.
- A canonical-JSON `targets.json` with per-artifact `length` and `sha256`.
- A TUF-style `signed + signatures` envelope (`targets-signed.json`).

`snapshot.json` and `timestamp.json` are generated on the air-gapped signing host during the final ceremony.
See [release-keys.md § Per-release signing flow](release-keys.md) for the full ceremony checklist.

---

## 6. Publish to GitHub Releases

```sh
gh release create v<VERSION> \
  dist/phlink-*.dmg \
  dist/phlink-*.AppImage \
  dist/phlink_*.deb \
  dist/phlink-*.rpm \
  dist/phlink-*.msi \
  dist/phlink-*.asc \
  dist/targets-signed.json \
  --title "phlink v<VERSION>" \
  --notes-file CHANGELOG.md
```

---

## 7. Post-release checklist

- [ ] GitHub Release page shows all artifacts with correct filenames.
- [ ] Each artifact's SHA-256 matches the value in `targets-signed.json`.
- [ ] GPG signatures verify: `gpg --verify phlink-*.AppImage.asc phlink-*.AppImage`.
- [ ] macOS `.dmg` mounts and launches correctly (Gatekeeper accepts it if Developer ID–signed).
- [ ] Windows `.msi` installs to `%LocalAppData%\phlink\` (test in a clean VM for production releases).
- [ ] `docs/user/install.md` references the correct new version tag.
